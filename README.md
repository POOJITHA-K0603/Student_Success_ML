# AI-Based Student Success & Personalized Learning Recommendation System

## Problem statement
Students who are falling behind are usually noticed too late, and generic advice ("study more") does not help. This project predicts a student's performance level (At risk / Average / High) from habits and topic mastery, groups students into learner types, and builds an optimised weekly study plan.

## Objectives
1. Predict risk level from academic and lifestyle features.
2. Discover learner groups from habits (unsupervised).
3. Allocate limited weekly study hours across topics to maximise predicted outcome (Genetic Algorithm).
4. Deliver all of this through a web app.

## Five questions (from the brief)
| Question | Answer |
|---|---|
| Problem | Early identification of at-risk students and tailored advice |
| Data | 1500 students, 13 input features (see below) |
| What ML learns | Mapping from habits/mastery to risk class; habit-based learner groups |
| Optimisation | GA chooses hours per topic under a weekly time budget |
| Application | Flask web app: input -> model -> risk + group + study plan |

## Unit I framing
- **Input:** 8 habit/score features + 5 topic-mastery scores (13 total).
- **Output:** class 0/1/2 = At risk / Average / High, then a study plan.
- **ML problem:** 3-class supervised classification (+ unsupervised grouping + optimisation).

## Dataset (synthetic, documented generator: `src/data_gen.py`)
- Records: 1500. Inputs: 13. Target: `risk` (quantiles of a hidden final score: bottom 25% At risk, top 25% High). `final_score` is saved but never used as an input.
- Four hidden learner archetypes are mixed; features are sampled around them with noise; score is non-linear (diminishing returns on study hours, interaction of study x participation, screen-time penalty) plus unobserved "motivation" and noise. ~2% missing values added to 3 columns.
- Features: attendance %, study_hours/day, prev_gpa (/10), assignment_score, quiz_score, sleep_hours, screen_hours (non-study), participation (1-5), mastery_{maths, programming, databases, ml_basics, communication} (0-100).
- **Limitation:** because the data is synthetic, the metrics show the pipeline works, not real-world accuracy. For the final review, replace `data/students.csv` with real data (class survey, or UCI Student Performance) keeping the same column names, then rerun `run_all.py`.

## Workflow (all outputs are in `results/`, generated by the code)
1. **EDA** `src/eda.py` -> histograms, correlation heatmap, boxplots by risk, missing-value summary.
2. **Preprocessing** (inside a single sklearn Pipeline, fitted on training data only to avoid leakage): feature engineering -> median imputation -> standard scaling.
3. **Feature engineering:** avg_mastery, min_mastery, engagement (attendance x participation), distraction_ratio (screen/(study+1)).
4. **Models compared** (`src/train_models.py`): Logistic Regression, Decision Tree, Random Forest, Gradient Boosting, MLP neural network. Metrics: accuracy, precision, recall, macro-F1, 5-fold CV F1, train-vs-CV gap, training time, confusion matrix, permutation importance.
5. **Overfitting check:** unpruned tree and default Random Forest reach 100% train accuracy but 79.7% and 85.3% test; validation curve in `overfitting_validation_curve.png`. Logistic Regression and the MLP show small gaps.
6. **Tuning:** GridSearchCV on Random Forest (n_estimators, max_depth, min_samples_leaf) and RandomizedSearchCV on the MLP (hidden layers, L2 alpha, learning rate). Tuning RF did not reduce its overfitting, so it was not preferred.
7. **Model selection rule (test set not used):** keep models within 1 std of the best CV macro-F1, then choose the one that overfits least. **Selected: Logistic Regression**, final held-out test accuracy 0.873, macro-F1 0.871 (`classification_report.txt`, `confusion_matrix.png`).
8. **Unsupervised (Unit III)** `src/clustering.py`: K-Means on 7 habit features + PCA. Why: no learner-type label exists, so clustering finds habit groups for tailored tips; PCA (2 components explain 73.7% of variance) lets us see the groups. Silhouette: k=2 is highest (0.349) but only splits good/weak habits, so k was searched from 3 upward; **k=3 chosen (silhouette 0.27)**.
9. **Neural network (Unit V):** `sklearn.MLPClassifier`, ReLU, Adam, L2 regularisation (alpha), early stopping, tuned. Compared with other models in `model_comparison.csv`; it matched them on test performance but did not beat Logistic Regression, so the simpler, more interpretable model was kept for deployment. (Dropout and batch normalisation need TensorFlow/PyTorch, not used here.)
10. **Genetic Algorithm (Unit IV)** `src/genetic.py`: chromosome = hours per topic (sum = weekly budget, max 8h/topic); fitness = model's expected success (0.5*P(Average)+1.0*P(High)) after hours raise mastery with diminishing returns `m + (100-m)(1-exp(-0.12h))` (the 0.12 learning constant is an assumption). Tournament selection, arithmetic crossover, Gaussian mutation, elitism. Over 30 at-risk test students (mean expected success): no extra study 0.077, equal split 0.124, weakest-two-topics 0.117, **GA 0.146** (`ga_comparison.csv`).
11. **App** `app/app.py`: sliders -> pipeline -> risk, probabilities, learner group tips, GA study plan.

## How to run
```
pip install -r requirements.txt
python run_all.py        # generates data, EDA, trains, clusters, GA, saves models and results
python app/app.py        # open http://127.0.0.1:5000
```
